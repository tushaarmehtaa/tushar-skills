# Copy quality and state rules

Read this reference before the final pass or when errors, progress, localization, destructive actions, or voice consistency are in scope.

## Preserve voice without preserving defects

Infer voice from strong existing product lines, customer language, and documentation. Record formality, warmth, technical density, contractions, casing, humor, person, and terminology. Preserve useful quirks; change wording that conflicts with state, consequence, accessibility, or factual behavior.

Allow tone to become calmer and more precise as stakes rise. Consistency means a coherent product, not identical cadence on every surface.

## Match language to state

- Actions name action and object when consequence is not obvious.
- First-use empty states differ from filtered zero, missing permission, sync delay, deletion, and unavailable data.
- Errors identify the failed action or object, preserved state, and recovery; state a cause only when known.
- Progress text claims only what the system measures or has actually started.
- Success appears after confirmation and names what changed when useful.
- Destructive dialogs identify object, consequence, reversibility, and affected data or collaborators.
- Disabled states expose requirements when users need to understand how to proceed.

## Protect factual integrity

Check material claims against repository or product behavior. Never invent statistics, customer proof, security guarantees, error causes, processing stages, or completion. If a needed fact is missing, preserve accurate existing copy or flag the content requirement outside the interface.

Keep hedges that communicate real uncertainty, probability, capability, risk, or time range. Remove only evasive or content-free qualification.

## Localization and accessibility

- Preserve complete grammatical units for translators.
- Avoid concatenating sentence fragments around variables.
- Specify plural and select branches for values that affect grammar.
- Check variable escaping, date/number units, locale formatting, and fallback behavior.
- Ensure accessible names distinguish repeated controls and match visible intent.
- Associate validation with fields and announce asynchronous status changes when needed.
- Test long translations, zoom, narrow viewports, and text expansion.

## Remove weak patterns contextually

Delete placeholder scaffolding, semantic duplication, fake urgency, generic praise, and slogans inside operational UI. Treat fashionable vocabulary, punctuation, fragments, contractions, passive voice, humor, emoji, and sentence length as evidence only when they repeat, obscure meaning, or break the established voice.

Do not rewrite every empty state into “No X yet,” every button into verb-plus-object, or every error into three sentences. Judge the whole component and surrounding context.

## Final flow review

Trace important journeys from entry to completion and recovery. Confirm the user can identify current state, consequence, next action, and safety without contradictory language. Check neighboring copy so a local improvement does not introduce terminology drift or duplicate another message.
