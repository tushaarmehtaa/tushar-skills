# Copy quality

Use this as the final pass for interface language.

## Preserve the product's voice

Before rewriting, identify several existing lines that sound natural for the product. Record its formality, warmth, technical density, contractions, casing, humor, and preferred domain terms. Keep useful quirks and calibrated uncertainty. Do not replace every voice with terse startup copy.

## Match copy to state

- Actions name the action and object when the consequence matters.
- Empty states distinguish first use, filtered zero, missing permission, and deleted or unavailable data.
- Errors state what failed, what remains safe, and the next recovery action. State a cause only when the system knows it.
- Loading text claims only progress the system can measure.
- Success text appears only after confirmation and names what changed.
- Destructive dialogs name the object, consequence, and reversibility.

## Remove weak patterns

Delete content-free narration, generic praise, fake urgency, semantic duplication, placeholder copy, and slogans inside operational UI. Treat fashionable vocabulary and punctuation as evidence only when repeated or mismatched; one em dash or fragment is not a defect.

Check every material claim against repository behavior. Never invent statistics, customer proof, security guarantees, or error causes. If a needed fact is missing, leave the existing accurate text or flag the gap outside the user-facing copy.

## Final checks

Read important flows aloud. Confirm terminology stays stable across navigation, forms, notifications, emails, and settings. Check interpolation, pluralization, overflow, localization, accessible names, and every meaningful state.
