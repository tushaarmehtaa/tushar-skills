## Triggering the scout

The daily scout is unattended, read-only, and already on cron. It never edits
the repo.

```bash
crontab -l                                    # 08:20 IST daily, hourly catch-up
bash scripts/run_seo_newsroom_scout.sh        # run now; no-ops if today exists
tail -f /private/tmp/slashskills-seo-newsroom-scout.log
```

Output lands in `workspace/seo-newsroom/runs/YYYY-MM-DD.md` (gitignored). The
script holds a lock and skips if a report for the current IST date already
exists. To force a re-run, delete that file first.

## Re-running the evals

All flags matter. `--scaffold` runs the fixture script, `--allow-tools Bash` is
required because the skill shells out to git, and `--no-publish` keeps the HTML
report local.

```bash
cd /Users/tushaarmehtaa/Dev/active/tushar-skills

# full behavioral ablation, ~$3.30, ~10 min
claude plugin eval . --scaffold --allow-tools Bash --trust-plugin \
  --no-publish -j 3 --max-cost-usd 15

# one case
claude plugin eval . --case changelog-normal --runs 3 --scaffold \
  --allow-tools Bash --trust-plugin --no-publish -j 3

# discovery probes only, single arm
claude plugin eval . --tag discovery --runs 5 --ablation none --scaffold \
  --allow-tools Bash --trust-plugin --no-publish -j 3
```

Results write to `evals/results/` (gitignored). Add `--json <path>` for machine
output and `--keep-temp` to preserve each run's sandbox for debugging.

### Three traps, learned the hard way

1. **Never conclude from one run.** A single run once showed delta -0.60 where
   the corrected suite at n=3 showed +0.57.
2. **Measure inside the eval sandbox.** An ad-hoc `claude -p` harness reported a
   discovery defect that did not exist: the session loaded 102 personal skills
   and a same-named `changelog` collided with the one under test. In the
   sandbox it is 15/15.
3. **Graders read `last_message`.** If a prompt does not say where the output
   goes, a run that writes a file scores zero for the wrong reason.
