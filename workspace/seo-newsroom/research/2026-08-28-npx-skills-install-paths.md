# `npx skills` installation-path verification — 2026-08-28

## Method

Observed `skills` CLI version 1.5.23 on macOS. Installed the checked-in `rate-limit` package with `--copy` into three isolated Git repositories, once per explicit `-a` target. For global scope, installed a uniquely named disposable package with `-g -a codex claude-code cursor --copy`, inspected the filesystem, then removed only that probe and confirmed it was absent.

Commands used the same scope and agent flags generated by Slashskills. `--copy` changed link strategy, not the runtime-facing destination. No catalog package was globally added or removed.

## Observed destinations

| Target | Project scope | Global scope | Evidence |
| --- | --- | --- | --- |
| Codex | `.agents/skills/<skill>` | `~/.agents/skills/<skill>` | CLI completion output and filesystem |
| Claude Code | `.claude/skills/<skill>` | `~/.claude/skills/<skill>` | CLI completion output and filesystem |
| Cursor | `.agents/skills/<skill>` | `~/.agents/skills/<skill>` | CLI completion output and filesystem |

The Claude Code pre-install summary displayed `.agents/skills`, while its completion output and actual filesystem destination were `.claude/skills`. Treat the latter as authoritative.

## Runtime documentation comparison

- OpenAI documents Codex repository discovery through `.agents/skills` from the working directory to the repository root and user discovery at `$HOME/.agents/skills`. Codex detects skill changes automatically.
- Anthropic documents `.claude/skills` for project and personal skills, direct `/skill-name` invocation, and live change detection.
- Cursor documents both `.agents/skills` and `.cursor/skills` at project and user scopes, plus Claude/Codex compatibility locations. The Slashskills installer currently chooses the shared `.agents/skills` destination.

This record verifies installer paths only. It does not mark any package runtime-tested; discovery, invocation, behavior, update, and removal still require the full `CONTRIBUTING.md` smoke test and a `runtime-verification.json` record.
