### Cursor self-hosted skill and MCP boundaries

- **Repository overlap:** `/guides/cursor` already owns installation scope and remote-agent behavior.
- **Precise correction:** replace “managed workers” with Cursor's “self-hosted workers” wording, distinguish repository/project skills from developer-local global skills, and explain that local command/stdin MCP execution occurs on the worker while remote HTTP/SSE services remain remote.
- **Privacy qualification:** do not turn “tool execution runs on your worker” into “nothing leaves your network.” Cursor documents that the worker sends the content required by the agent, including file content, terminal output, diffs, screenshots, local MCP results, and routing metadata.
- **Recommendation:** update the existing guide. Do not create a self-hosted Cursor article.

### Codex 0.153 marketplace and MCP approvals

- **Material signal:** the release adds remote marketplace list/install/remove behavior and scopes remembered MCP approvals to the selected app account.
- **Repository gap:** Slashskills distributes standalone skills and has no checked-in plugin artifact or remote-marketplace fixture.
- **Verification gap:** today's local Codex is 0.152.1, so the new behavior was not exercised.
- **Recommendation:** use an isolated 0.153.0 environment, one harmless plugin, and two mock app accounts. Preserve list/install/remove, installed-path, approval-isolation, and rollback traces before editing public guidance.
- **Readiness cap:** 59 because the timely angle currently has authoritative release evidence but no owned execution evidence.
