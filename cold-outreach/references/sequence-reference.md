# Sequence examples

These examples show distinct jobs, not a mandatory cadence. Replace every claim with verified sender evidence.

## Compact email sequence

### Touch 1 — relevance and ask

```text
Subject: [specific verified signal]

Hi [Name] — noticed [signal]. We help [comparable user] [outcome] by [mechanism], and [verified proof].

Worth sending a short example for [their context]?
```

### Touch 2 — clarify or lower friction

```text
Hi [Name] — one clarification: [brief point that prevents a likely misunderstanding].

If a call is premature, I can send [small useful artifact] instead.
```

### Touch 3 — value without an ask

```text
This [resource/checklist/example] may be useful given [signal]: [link]. It covers [specific value].
```

The artifact must be genuinely useful and safe to open. Do not disguise another pitch as “value.”

### Touch 4 — verified proof

```text
[Comparable customer/context] changed [metric] from [before] to [after] over [period] using [mechanism]. The relevant similarity is [specific mapping].

If useful, I can walk through the implementation constraints.
```

Skip this touch when proof is not nameable, comparable, and authorized.

### Final touch — close

```text
I’ll close the loop here. If [problem] becomes a priority later, the easiest way to reach me is [channel].
```

## Multichannel variation

- Connection request: accurate reason to connect; no compressed pitch required.
- Public engagement: participate only when there is something genuine to add.
- Email: carry the substantive relevance and ask.
- Direct message: use only for a channel-appropriate clarification, not a duplicate email.

## Stop-condition record

```text
Positive reply: human owner within [service level]
Question/objection: cancel remaining touches; respond in thread
Referral: verify permission and context before contact
Out of office: pause to return date
Opt-out/complaint/bounce: suppress across all channels
No response after final touch: stop
```
